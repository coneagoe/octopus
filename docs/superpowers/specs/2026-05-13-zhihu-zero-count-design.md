# 日报中明确显示知乎 0 条设计

## 问题

当前 `scripts/summarize.py` 只有在 `entries_by_source['zhihu']` 非空时才会输出“## 知乎回答”章节。

这意味着当知乎抓取流程正常执行、但当天确实没有抓到新内容时，日报里不会出现任何知乎相关提示，读者无法区分：

1. 知乎成功抓取但结果为 0 条
2. 知乎抓取失败或根本没有产出可用输入

## 目标

1. 当知乎抓取成功且结果为空时，在日报中明确显示“知乎 0条”。
2. 展示形式固定为：
   - `## 知乎回答`
   - `_知乎 0条_`
3. 不把这条提示计入日报总条数。
4. 不为这条提示生成 AI 点评。
5. 保持其余来源（RSS、网站、飞书、邮件）现有行为不变。

## 非目标

1. 不改变知乎抓取逻辑本身。
2. 不把知乎失败伪装为“0 条”。
3. 不修改缓存文件的数据结构。
4. 不调整 `_今日无新内容_` 的现有整体空日报语义。

## 方案对比

### 方案 A：显式传递“知乎抓取成功”状态（采用）

- `main()` 在读取知乎缓存后，显式判断这次知乎输入是否可视为“成功抓取完成”。
- `generate_markdown()` 接收一个新的布尔参数，例如 `zhihu_fetch_succeeded`。
- 当 `zhihu_fetch_succeeded` 为真且知乎列表为空时，输出知乎章节和 `_知乎 0条_`。

优点：

- 能准确区分“成功但 0 条”和“失败/缺失”。
- 语义清晰，测试边界明确。
- 不污染现有缓存数据结构。

缺点：

- 需要把一小段状态从 `main()` 传入 `generate_markdown()`。

### 方案 B：构造一条伪知乎 entry 表示“0 条”

优点：

- 表面上可以少改分支判断。

缺点：

- 会把“无数据”伪装成“有一条数据”。
- 容易误伤总条数统计和点评逻辑。
- 数据语义变差。

### 方案 C：仅根据缓存文件是否存在来推断“成功且 0 条”

优点：

- 改动最少。

缺点：

- 对历史残留文件或异常内容不够稳健。
- 难以准确表达“本次抓取成功”的语义。

## 最终设计

采用 **方案 A**。

`scripts/summarize.py` 在生成 Markdown 时，不再仅仅依据知乎列表是否为空来决定是否显示知乎章节，而是同时参考一个显式的“知乎抓取成功”状态：

- **成功且有内容：** 保持现有行为，输出知乎条目列表。
- **成功但 0 条：** 输出 `## 知乎回答` 和 `_知乎 0条_`。
- **失败或输入缺失：** 保持现有行为，不输出知乎章节。

## 详细设计

### 1. 成功判定边界

本次需求里的“抓取到确实为 0”定义为：

- 知乎缓存文件存在；
- 文件成功解析；
- 解析结果是一个列表；
- 列表长度为 0。

若知乎缓存文件不存在、无法解析、或内容不符合预期结构，都不视为“成功抓取但 0 条”，因此不输出“知乎 0条”提示。

### 2. Markdown 生成规则

`generate_markdown()` 新增一个显式参数，用来控制知乎空状态的显示。

具体规则如下：

1. 若 `zhihu_entries` 非空：
   - 保持现有“## 知乎回答”章节和逐条渲染逻辑不变；
   - 这些真实条目继续计入 `total`。
2. 若 `zhihu_entries` 为空且 `zhihu_fetch_succeeded` 为真：
   - 输出：
     - `## 知乎回答`
     - `_知乎 0条_`
   - 不增加 `total`
   - 不调用 `generate_commentary()`
3. 若 `zhihu_entries` 为空且 `zhihu_fetch_succeeded` 为假：
   - 与当前行为一致，不输出知乎章节。

### 3. 与整体空日报的关系

`_知乎 0条_` 只是一个来源级提示，不代表当天有真实内容。

因此：

- 只有真实内容才计入底部“共 X 条内容”统计；
- 如果当天所有来源都没有真实条目，即使知乎章节显示了 `_知乎 0条_`，仍然保留 `_今日无新内容_`。

这样日报可以同时表达两层信息：

1. 当天没有新增内容；
2. 知乎并非失败，而是成功抓取后结果为 0 条。

### 4. 测试

补充 `test/test_summarize.py` 的回归测试，至少覆盖以下场景：

1. **知乎成功且 0 条**
   - 断言输出包含 `## 知乎回答`
   - 断言输出包含 `_知乎 0条_`
   - 断言底部总条数仍为 `0`
   - 断言 `_今日无新内容_` 仍保留（在其余来源也为空时）

2. **知乎输入缺失或未标记成功**
   - 断言不输出知乎章节

3. **知乎有真实条目**
   - 断言维持现有知乎条目渲染行为

## 风险与缓解

- **风险：** “缓存文件存在”被误当作“本次抓取成功”。  
  **缓解：** 设计要求同时验证“成功解析为列表”，而不是只看文件存在与否。

- **风险：** 新增空状态后影响总条数统计。  
  **缓解：** 明确规定 `_知乎 0条_` 不计入 `total`，并用测试锁住。

- **风险：** 读者把 `_今日无新内容_` 与 `_知乎 0条_` 视为矛盾。  
  **缓解：** 两者语义不同：前者表示“全局无新增”，后者表示“知乎来源成功执行但产出为 0”。

## 实施轮廓

1. 在 `scripts/summarize.py` 中引入知乎抓取成功标记，并把它传给 Markdown 生成函数。
2. 在知乎分支新增“成功但 0 条”的来源级空状态输出。
3. 在 `test/test_summarize.py` 中补回归测试，锁定显示文案和总条数行为。
